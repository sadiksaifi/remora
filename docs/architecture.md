# Architecture

Remora is a native macOS remote desktop client. RDP uses FreeRDP 3.x. VNC uses LibVNCClient behind the same session interface.

This is personal software. Prefer an existing library or a FreeRDP built-in over writing our own. Write code only where nothing suitable exists.

## Platform

- macOS 26.0 and later, arm64 only.
- Swift 6 language mode with complete strict concurrency.
- AppKit for the window, menus, the connection list, and the session view. SwiftUI in `NSHostingController` or `NSHostingView` for sheets, Settings, session status views, and the tab strip.
- Apple's macOS 27 Human Interface Guidelines are the design baseline. Liquid Glass comes from standard AppKit and SwiftUI controls and the SwiftUI glass effect.
- The renderer and shortcut-capture demo harnesses compile only in Debug builds.
- No App Sandbox. Hardened runtime only when we notarize a release.

## Layout

```
Remora.xcodeproj           app target, synchronized folders
Remora/                    AppKit app, SwiftUI sheets, Metal renderer
RemoraCLI/                 bundled Swift Argument Parser executable
Packages/RemoraKit/
  RemoraCore               session protocol, connection model, connection store, credentials, neutral input
  RemoraControl            Codable control messages and Network.framework Unix sockets
  CFreeRDPBridge           plain C bridge; the only code that includes FreeRDP headers
  RDPSession               Swift RDP adapter implementing the session protocol
  CVNCBridge               plain C adapter, socket lifecycle, LibVNCClient callbacks
  VNCSession               Swift VNC adapter and independent input ownership
Vendor/build-engine.sh     builds static RDP and VNC XCFrameworks sharing OpenSSL
```

## Window and tabs

Remora has one main window. Its home page is the connections list. Each open session is a tab in the same window. Native window tabbing is off (`tabbingMode = .disallowed`), because native tabs are separate windows and window managers such as AeroSpace, yabai, and Rectangle would see one window per session.

- `SessionTabs` owns the tabs: one per connection, in opening order, with the selection (nil for home) and each tab's session state. The connections list, the tab strip, the toolbar, and the Window menu observe it.
- `SessionViewController` is one tab's page. It owns the session, its renderer and desktop view, the overlays, the clipboard sync, and its credentials and certificate sheets.
- `MainWindowController` shows the selected page, owns the toolbar, and routes the Session and tab menu actions to the shown tab.

The toolbar shows the title "Connections", the + button, and search while no tab is open. With tabs open, the title hides, a Home button follows the traffic lights, and the tabs sit between two flexible spaces. The toolbar draws its glass capsule around the tab strip, centers it, and lets it grow to its ideal width (220 points per tab). Past that the tabs share the available width and finally scroll. Tab contents follow Safari's compact tabs. The title is centered, with the status dot to its left. The shown tab and the tab under the pointer show two controls: a close button (`xmark.circle.fill`) at the left end and a menu button (`slider.horizontal.3`) at the right end. Other tabs show neither. Both sit in the title's 24-point side padding, so the title stays centered and truncates between them. Tabs share the width equally, but the shown tab keeps at least 132 points, taken from the other tabs down to their 76-point minimum. The menu button hangs that tab's menu under it, including on a hovered tab that is not shown, and its items act on that tab without selecting it: Capture Keyboard with a checkmark, Show Key Presses with a checkmark, a separator, Take Screenshot, Copy Screenshot, and the recording item with their shortcuts, a separator, then the tab context menu's items, ending with Close Tab. Capture Keyboard is enabled only on the shown, connected tab, because only its desktop is in the window. AppKit has no public menu with Safari's arrow, so it is a plain pop-up menu centered under the button. Secondary-clicking a tab shows the context menu, which has the same items without the first two groups. `MainWindowController.tabMenu(for:includingActions:)` builds both, and `makeCaptureItems()` builds the capture items for this menu and the Session menu. The tab's accessibility element sorts first, then VoiceOver reaches the menu button as its own element. Closing stays a "Close Tab" action on the tab. The search item collapses to a button through a low-priority width on its field. On home it filters the list; on a tab it offers saved connections through `NSTextField.suggestionsDelegate`. On a tab, Escape works like a native search field: the first press closes the suggestions, and the next clears and closes the search and gives the keyboard back to the desktop.

A hidden tab's desktop leaves the window. Its display link stops, so it presents no frames, and its human-held keys, buttons, and keyboard capture are released. Its session stays connected and asks the server to stop sending desktop updates unless recording or CLI frame demand keeps them on. `SessionDisplay` does the same while the window is minimized or fully covered (`NSWindow.occlusionState`). Showing the tab redraws the last frame at once, turns updates back on with a refresh of the whole desktop, and requests the current size for Fit to Window. A credentials or certificate request on a hidden tab marks the tab with an orange dot and waits; its sheet appears when the tab shows. Tabs can't change while the window has a sheet.

Closing a tab disconnects its session. Closing the window keeps every tab and its session.

## Menu bar and Dock

Remora runs from the menu bar. The `terminal` menu bar icon shows while Remora runs. The Dock icon shows only while the main window or Settings is open, including minimized. `AppDelegate` switches the activation policy between `.regular` and `.accessory` when either window shows or closes. Launched with `--cli-background`, Remora starts as `.accessory` with no window.

`StatusMenu` owns the icon. It builds its menu each time the menu opens, so it has no observers or timers. Each tab is an item with its status dot, its name, the state as the subtitle, and a submenu: Show, then Disconnect while the session is live. Then come Open Remora, Settings… and Quit Remora. With no tabs, a disabled No Sessions comes first. `sessionItem(for:)` builds one tab's item and submenu.

The red close button closes the window, and its sessions stay connected. A closed window counts as covered, so `SessionDisplay` stops desktop updates unless the tab records or has CLI frame demand. Launching Remora from Finder, Spotlight or the Dock while it runs shows the window through `applicationShouldHandleReopen(_:hasVisibleWindows:)`. Command-Q, Dock menu Quit and Quit Remora ask "Quit Remora and disconnect N sessions?" while any session is live, and add "Recordings in progress are saved." while a tab records.

## Control socket

The `remora` executable ships at `Remora.app/Contents/Helpers/remora`. Settings installs a symlink at `~/.local/bin/remora`. The helper resolves symlinks to find its containing app bundle. The agent guide ships at `Remora.app/Contents/Resources/skills/remora/SKILL.md`. `remora help agent` prints it, and Settings and `remora skill install` link that folder as `remora` into the shared Agent Skills folder `~/.agents/skills`, which Codex, OpenCode, pi, Muse, Antigravity, Cursor, FX and other agents read, and into Claude Code's `~/.claude/skills`. They own only links to this copy. A build step parses every `remora` command line in the guide with the CLI's own parser. Both targets link RemoraControl, which owns the Codable request, response and event types and the Network.framework Unix-domain client and server. RemoraControl depends on neither FreeRDP nor the Keychain. `CommandLineController` maps requests onto the app's stores, tabs, sessions and captures.

The listener runs whenever the app runs, whether the CLI is installed or not. Its path is `/tmp/remora-<uid>/control.sock`, with mode `0600` inside a directory with mode `0700`. There is no authentication, token, peer check or approval prompt. Installing the CLI symlink is the only opt-in. `REMORA_SOCKET` is an undocumented development override for both processes, used to isolate parallel builds.

Each connection carries one JSON-line request and one JSON-line reply. Requests contain `command`, an optional `session`, an optional `timeout` in seconds, and `arguments`. Replies use `{"ok":true,"result":{...}}` or `{"ok":false,"error":{"code":"...","message":"...","hint":"..."}}`; failures may include `details`. `events` keeps the connection open for NDJSON, beginning with a snapshot. `screenshot --output -` receives a JSON reply with `result.byteLength`, followed by that many raw PNG bytes. The helper writes only the PNG to stdout for that command.

When the app is absent, the helper asks Launch Services to open its bundle without activation and with `--cli-background`. It waits up to ten seconds for the socket, separately from the command deadline. It never resends a mutation after a lost reply; the caller must inspect current state before retrying.

## Control state machine

`SessionControl` in RemoraCore owns input policy as a pure state machine. `SessionViewController` applies its decisions to input, clipboard synchronization and frame demand. Its states are:

- `idle`: no agent is attached, and human input is forwarded.
- `active`: CLI input has attached the agent. Human clicks, keys and scrolls stay local while local menus remain available.
- `paused`: the human chose Take Over. Agent input fails with `user-active` until an explicit Resume.
- `stopped`: Stop Agent Control detached the agent and restored human input. This is a soft stop; the next CLI input attaches again.

Take Over moves `active` to `paused`. Stop moves `active` or `paused` to `stopped`. Both first close input admission, cancel queued agent input and await release of its held keys and buttons before forwarding human input. Take Over emits `user.tookOver`; Stop emits `control.stopped`. Resume moves `paused` or `stopped` to `active` and emits `user.resumed` with click, key and scroll counts and `screenChanged`, never typed text. There is no automatic resume timer. Agents must wait for the human to Resume rather than invoke Resume themselves.

Resume requires a new CLI screenshot before the next input, or the command fails with `observation-required`. A screenshot taken while paused does not clear that requirement. Desktop geometry changes expire screenshot mappings; input with an old `--image` receipt fails with `image-expired`. Each session admits one pointer, key, text or batch input command at a time; overlapping commands fail immediately with `input-busy`. Session end cancels input and moves active control to `stopped`, preserving a human pause. Manual reconnect replaces the session attempt UUID, so old session targets and screenshot mappings expire.

The RDP adapter tracks held input per source. Focus changes release human input only. Agent requests release their own held state on every exit, including cancellation and timeout. Showing or focusing an agent-controlled tab does not release agent keys, synchronize lock keys, capture the keyboard, or show the shortcut-permission banner.

Mac clipboard synchronization follows human ownership, independently of who opened the tab. It is disabled during active agent control and handover. It can resume while paused or stopped only when the connected desktop is visible, focused and in the active key window. CLI `clipboard get` reads remote text without attaching control. `clipboard set` attaches control and obeys the same pause and observation checks as input. Neither command accesses the Mac clipboard.

`SessionDisplay` enables desktop updates while the desktop is visible, recording runs, or CLI frame demand is nonzero. Active and paused control retain background frame demand. Stop drops that demand. Connect, reconnect, resize, screenshot, frame waits and recording start hold temporary demand while waiting for frames. When no consumer needs frames, Remora requests RDP Suppress Output. A server without suppression support keeps sending updates. Re-enabling updates requests a full refresh. These demands do not start the hidden view's display link. An idle app with no sessions has no polling timer or drawing work.

A 38-point glass capsule at the top center of the desktop shows "<agent> is in control" with Take Over, or "You're in control. <agent> is paused." with Resume. Stop Agent Control shows "<agent> can no longer control this session." without a button for four seconds, then fades the capsule. The tab replaces its status dot with `pointer.arrow.motionlines`, blue while active and gray while paused or stopped. The marker has no action. A recording marker follows it when both apply.

`SessionOverlayState` owns the agent cursor, independently of tab visibility. `applyControl()` shows it exactly while control is active. Attach places it at the last agent position, otherwise the last remote pointer position, otherwise the desktop center, and starts the appear spring. The first travel starts immediately. Take Over and Stop hide it with the same spring toward zero and keep its position. Resume shows it again. Session end hides and resets it; reconnect already resets the input overlay state. Tab switches, minimization, and occlusion leave the model alone. A desktop size or overlay unit change places the cursor at the same remote pixel without travel.

`CursorMotion` in RemoraCore ports the Codex cursor kit's travel, heading, shape, press, appear, and thinking springs. `CursorTuning` holds motion constants; `CursorStyle` holds artwork shared by both renderers. The glyph has a 1.39-point round-join outline and a fixed slate fill. Its halo uses sRGB (47, 74, 98) with the kit's radial alpha stops and white lift. No wallpaper access is involved. A click presses the glyph instead of drawing an agent click ring. Human click rings and the server's human cursor keep their recording behavior. `showAgentPointer` keeps its key and true default and selects the screen cursor. `showPointerInRecordings` independently selects recorded pointers and human rings. Screenshots exclude every pointer, ring, and key pill; the control capsule is excluded from all captures.

The executor marks the cursor busy at input admission and idle on every exit. While active and idle, it sways from 0.5 seconds through just before 30 seconds after the last command ended. Sway starts at phase zero and hands its offset to the heading spring when it stops. The controller reads and observes the workspace's Reduce Motion setting. Reduce Motion replaces travel with a 0.1-second fade out, placement, and a 0.1-second fade in, disables sway and stretch, and makes appear a fade. Press feedback remains.

The tab actions menu, tab context menu and Session menu offer Take Over or Resume, Stop Agent Control and Stop All Agent Control. Tab menus hide actions that do not apply; the Session menu disables them. The menu bar status item lists each session with its state and "Started by <name>", plus a submenu with Show, applicable control actions and Disconnect for a live session. Its app actions are Open Remora, Stop All Agent Control, Settings… and Quit Remora. Stop All Agent Control is disabled when no agent can be stopped. The agent name is a display-only label from the CLI's nearest non-shell ancestor process, falling back to "remora CLI". The session's starter is recorded separately from the program that last attached control.

## CLI lifecycle

CLI startup opens no window, does not activate Remora and shows no Dock icon. The menu bar icon remains available. Help, `app status` and `settings cli get` work without launching the app; command discovery through `capabilities` without a session is also local. `app show` opens and activates the main window or Settings, and a foreground `connect` shows the main window. Opening either window restores the Dock icon.

`app hide` hides the app. `app close` closes the main window. Both preserve sessions, as does the red close button. Closing the last window leaves Remora in the menu bar. Opening Remora from Finder, Spotlight or the Dock shows the main window even if the app is already running.

Quit paths are Command-Q, Dock menu Quit while a window is open, Quit Remora in the menu bar, and `remora app quit`. The human paths use the session confirmation described above, with Quit as the default button and Cancel available. `app quit` skips confirmation. Every quit path disconnects sessions and finishes recordings, including captures retained after their tabs closed, before stopping the socket listener. App termination bounds recording cleanup to ten seconds.

## Session interface

One Swift protocol in RemoraCore. The app never sees FreeRDP types.

- Commands in: connect, disconnect, key, pointer, wheel, request resize, display updates on or off, local clipboard text.
- Events out: state (connecting, awaiting credentials, awaiting trust, connected, reconnecting, disconnected with a typed reason), desktop size, cursor, remote clipboard text.
- Frames go to an injected frame sink, not through the event stream.
- A resize request is not a size change. Only the desktop size event resizes the renderer.

## Threading

- Each session owns one dedicated thread. It runs `freerdp_connect`, the event loop, and every FreeRDP call.
- Input, resize, display update, clipboard, and disconnect commands go through a locked queue plus a wake event in the event loop's wait set.
- Display updates use Suppress Output (MS-RDPBCGR 2.2.11.3). Turning them back on also sends Refresh Rect for the whole desktop. FreeRDP sends neither PDU to a server that doesn't advertise support, and that server keeps sending updates. A reconnected server starts with updates on, so the bridge sends the current choice again.
- `freerdp_abort_connect_context` is the only cross-thread FreeRDP call.
- FreeRDP callbacks arrive on several threads (GFX and Display Control on the dynamic channel thread, clipboard on its own). The bridge copies data upward and never assumes a thread.
- Credential and trust callbacks block the session thread on a condition variable until the MainActor answers.
- Frame pixels are borrowed for the duration of the frame callback only. FreeRDP replaces the buffer on resize.

## Rendering

`CAMetalLayer` with one private BGRA texture. The renderer copies dirty rectangles into shared staging buffers, then blits the accumulated damage and draws one opaque quad in the same command buffer. Semaphores prevent CPU writes while the GPU reads a staging buffer. `NSView.displayLink` paces presentation, with at most one command buffer in flight. Pending damage coalesces instead of queueing frames; an idle desktop submits no GPU work. Pixels are tagged sRGB. Scaling uses aspect fit with black letterboxing, nearest sampling at 1:1, and linear sampling otherwise.

## Desktop sizing

Connections default to Fit to Window, including saved connections without a resolution key. Fit to Window connects at the tab's content size in backing pixels and announces the display's backing scale. Display Control follows window resizing, screen changes, full-screen transitions, and the tab showing again.

A fixed resolution stores a width and height in remote pixels in RemoraCore. Each side must be 200 to 8192 pixels, and the width must be even. Fixed sessions connect with those dimensions and scale 1 (DesktopScaleFactor and DeviceScaleFactor 100). The RDP adapter rejects resize requests and disables Display Control negotiation for their lifetime, including automatic reconnect and GNOME's redirected reconnect through FreeRDP's original settings backup.

The window never resizes for a session. Fixed sessions and unrequested server desktop sizes render with aspect fit and letterboxing in the tab's content area below the toolbar. Fit to Window follows that area's size. In full screen the toolbar hides until the pointer reaches the top, and Fit to Window requests the screen size. The renderer and pointer mapping share `DesktopGeometry`; letterbox bars do not send pointer input.

## Input

`AgentInputSession` in RemoraCore is the common automation contract for RDP and VNC. `RemoteSession` is the human input boundary. Its injected feedback callback reports admitted human input and acknowledged agent input, including Unicode text, physical scancodes, pointer coordinates, button changes, and source releases. It uses the same WinPR Apple-to-scancode mapping as the transport. Local shortcuts and refused agent commands produce no feedback. Each controller owns a lock-protected `SessionOverlayState`; transport callbacks update it without scheduling a task per input event. Source releases and reconnects clear held modifiers and buttons.

`InputPlan` adds cursor operations around the existing protocol events. At each cursor step the main-actor executor checks whether the tab's desktop is in an unoccluded window with `showAgentPointer` enabled, or the tab is recording with `showPointerInRecordings` enabled. An unpresented cursor places directly and adds no waits. Presented moves travel and wait for arrival before submitting the pointer event. Scroll travels to its location before pointer and wheel submission, without a press. Click and drag wait 0.05 seconds after arrival, press to 0.78 or 0.86, and submit the real event 0.10 seconds after press start. Click retains its 20 ms down/up interval. Later clicks retain their 80 ms interval before the next press. Drag retains its straight samples and `durationMs` pacing, pinning the cursor tip to each successfully submitted sample. Raw button down travels and presses before submission; raw button up travels, submits, and releases. Keyboard, text, and delay actions add no cursor steps. Batches use the same per-action operations. Moves shorter than 0.5 points place without travel or an arrival wait.

Cursor waits use the delay loop's 10 ms cancellation checks, including handover, disconnect, session replacement, and geometry expiry. Before each wait the executor reserves one second before the deadline plus the remaining original input delays. If the cursor wait cannot fit, it places directly and skips all remaining cursor waits in that command. The 60-second intended-duration validation excludes cursor time. The acknowledgment stays `protocol-submission`: completion follows the last submission and cursor release, without waiting for the release spring.

`KeyPressDisplay` in RemoraCore names remote keys, with Command displayed as Win. Human events supply layout-aware printable characters; agent physical keys use their key names and Shift state, and Unicode input supplies literal text. Consecutive text keeps the last 32 characters. Consecutive identical chords display a repeat count. The bottom-center key pill disappears after 1.5 seconds, with an eased fade during the last 0.25 seconds. `showKeyPresses` defaults to false and controls the pill on screen and in all recordings of the session. The General settings pane and every tab's Show Key Presses menu item change it for all tabs. Under that switch, a size slider with small and large text glyphs at its ends sets `keyPressSize` from 0.75 to 2 times the standard size in steps of 0.25. It defaults to 1, is disabled while `showKeyPresses` is off, and applies on screen and in recordings.

The pill is a glass capsule beside the agent control capsule. `KeyPressPill` in RemoraCore owns its content, layout, and placement, in desktop pixels for both the screen and recordings. At the standard size the capsule is 44 points tall. Typed text is 22-point SF Pro Semibold on the glass. Keys and shortcuts sit in 34-point capsule keycaps inset 5 points from the edge, with 16-point SF Pro Semibold, so `Ctrl+Alt+Delete` reads as three keys without plus signs, and a repeat count follows in the secondary color as `×3`. A whitespace-only run shows a Space keycap. `KeyPressPill` measures text with Core Text at the drawn size, because SF Pro's tracking changes with its optical size. One point is the session's backing scale, but at least the desktop height divided by 1080, so large fixed desktops stay legible. The screen scales the entire layout and placement with the desktop picture. A Fit to Window Retina session keeps the standard capsule at 44 view points tall. The pill's bottom sits 64 points above the desktop's bottom edge, clear of a Windows taskbar or a dock, and shrinks to fit narrow desktops.

On screen, `AgentPointerView` hosts `KeyPressCapsule`, a SwiftUI view with `.glassEffect(.regular, in: .capsule)`, keycaps filled with `.quaternary`, and the count in `.secondary`. It uses the shared desktop layout scaled to view points and fades it in and out over 0.25 seconds. A frame cannot hold Liquid Glass, so recordings draw a rendition of it with Core Image: the desktop inside the capsule is blurred, saturated, and tinted for the window's appearance, under a Core Graphics image with the shadow, a hairline rim brighter at the top, keycaps, and text. The dark tint was matched to screen captures over light and dark desktops. `AgentPointerView` reports the window's appearance through `SessionOverlayState.setDarkAppearance`. Both new switches and `keyPressSize` use the shared `SettingKey` definition for CLI discovery and generated help; `remora settings set keyPressSize` rejects values outside 0.75 to 2.

- The session view is first responder and handles `keyDown`, `keyUp`, `flagsChanged`, and `performKeyEquivalent`.
- Key events carry the macOS virtual key code. RDP maps it with WinPR's Apple keycode table to scancodes.
- Physical mapping: Command is Windows/Super, Control is Control, Option is Alt.
- The keyboard layout announced to the server follows the current Mac input source.
- Human-held keys and buttons are released when the window loses key status, the app deactivates, or the tab hides. Modifiers still held when the key state resets stay out of the remote state until released.
- Scroll accumulates into 1/120-notch wheel units.
- System shortcuts (Cmd-Tab, Cmd-Space) are captured with a `CGEventTap` while a session tab shows, its desktop has the keyboard, and the window is key. This needs the Accessibility permission. Without it, or with capture turned off in Settings, those shortcuts stay local.
- Cmd-Q and Ctrl-Cmd-F always stay local, and so does the Ctrl-Option-Cmd family: `[` and `]` for the previous and next tab, 1 through 9 for tab N, H for the connections list, W to close the tab, S to save a screenshot, Shift-S to copy one, R to start or stop recording, and Escape to release the keyboard, like Session > Release Keyboard Capture. Clicking the desktop captures the keyboard again. Ctrl-Option-Cmd-arrows are left to window managers such as Rectangle. Other menu shortcuts, including Cmd-W, act only while the desktop does not have the keyboard.
- Session > Send Ctrl-Alt-Delete sends Control, Option, and Forward Delete through the ordinary key path.
- The tab menu's Capture Keyboard item shows whether the shown tab's desktop has the keyboard: it is first responder of the key window, the app is active, and the session is connected. `SessionTabs.Tab.isKeyboardCaptured` carries that state. System shortcut capture follows the same state. The item shows a checkmark while captured and toggles capture. Clicking the desktop captures the keyboard. The tab strip shows no capture state, because the desktop holds the keyboard nearly all the time while a session tab is in use, and the toolbar has no keyboard control. The shown, connected tab offers a "Capture Keyboard" or "Release Keyboard Capture" accessibility action, and the desktop element reports the state (see Accessibility).

## Accessibility

VoiceOver users and agents that drive Remora through the accessibility API read the same elements. Identifiers are stable lowerCamel strings. An element that can exist once per tab or connection ends in `-<UUID>`, the connection's immutable ID. A tab's ID is its connection's ID.

### Remote desktop

A connected desktop is one element. The remote computer's apps are pixels, not accessibility elements. An agent reads them from a screenshot and acts with pointer and key events. The element is `RemoteDesktopView`:

- Role `AXGroup`, role description "Remote desktop", description "Remote desktop, <tab title>", identifier `remoteDesktop-<UUID>`. `AXPosition` and `AXSize` are the view's frame, including any letterbox bars.
- `AXValue` lists the session status, the keyboard state, and any recording, separated by commas: "Connected, keyboard captured", "Reconnecting, attempt 3 of 20, keyboard released", "Connected, keyboard captured, recording", or "Connected, keyboard released, finishing recording". "Keyboard captured" means the desktop has the keyboard as defined in Input: first responder of the key window, app active, session connected. A change posts `AXValueChanged`. The keyboard state lives here, not in the tab's value, because the desktop holds the keyboard nearly all the time.
- `AXFocused` is true while the desktop is its window's first responder, and is settable. Setting it to true captures the keyboard through `SessionViewController.focusDesktop()`, the same path as a click; false releases it. `AXPress` captures the keyboard and never sends a click to the remote computer. A custom action, "Capture Keyboard" or "Release Keyboard Capture", toggles it.
- Keys reach a captured desktop by two routes: events from the session event tap, and AppKit key events delivered to the focused desktop. Both work only while the keyboard is captured as above, and both follow one local-shortcut policy. The tap consumes the events it sends to the remote computer before AppKit dispatches them, so no key arrives twice. A reserved local chord stays local until its keys are released. When an event carries only aggregate modifier flags, Remora keeps the left or right sides it already knows and ignores keys still held from before a focus change. Losing focus and recovering the tap both release every remote key.
- `AXHelp` says that remote apps are not accessibility elements, that Control-Option-Command-Escape releases the keyboard, and that Command acts as Windows or Super, Control as Control, and Option as Alt. Once a frame has drawn, it also gives the geometry in view points, for example: "The remote screen is 2560 by 1440 pixels, drawn at x 0, y 22.75, 1512 by 850.5 points in this view, at 0.590625 points per pixel, from the top left."
- One child is an `AXImage` described as "Remote screen", identifier `remoteScreen-<UUID>`. Its value is the remote size in pixels as `WIDTHxHEIGHT`, such as `2560x1440`. Its frame is the drawn area without letterbox bars, in the same top-left screen points as every `AXPosition`. To map a screen point to a remote pixel: `remoteX = (x - AXPosition.x) * WIDTH / AXSize.width`, and the same for y with the height. Pointer events use points, so do not apply the backing scale again. The size changes post `AXValueChanged` on this element.

`DesktopGeometry` computes both the help text and the child's frame, as it does for drawing and pointer input, so all three agree. A child element is the least code that hands an agent machine-readable geometry: AppKit has no public API for custom attributes, and standard frame and value attributes need no parser beyond splitting on `x`. The other children are the overlays drawn on the desktop: the reconnecting status, the permission banner, and the screenshot note.

### Tabs

- Each tab is a button element labeled with its title, identifier `tab-<UUID>`. Its value is the session status, with "recording" or "finishing recording" appended, and the shown tab has the selected trait.
- Pressing a tab shows it. Every tab, shown or not and with or without the pointer over it, has a "Show Tab Actions" action that opens the tab's menu, the same menu as the menu button. It hangs under the menu button when one shows, otherwise under the tab. Other actions are "Close Tab", "Stop Recording" while that tab records, "Capture Keyboard" or "Release Keyboard Capture" on the shown, connected tab, and "Show Key Presses" or "Hide Key Presses" on every tab.
- The menu button on the shown or hovered tab is labeled "Tab Actions, <tab title>", identifier `tabActions-<UUID>`.

### Session screens

- Status screens use `sessionCancel` while connecting or reconnecting, and `sessionClose` and `sessionReconnect` after a session ends. These have no suffix: only the shown tab's page is in the window. Escape cancels a connection attempt. After a session ends, Escape closes the tab and Return reconnects.
- When a status screen replaces the desktop and no other view has the keyboard, the status screen takes it. After a session ends, Close has the keyboard focus when the screen appears, Tab moves to Reconnect, and Shift-Tab moves back. A hidden tab does this when it shows. A search field in use keeps the keyboard.
- Remora posts an accessibility announcement when automatic reconnection starts (`Reconnecting to “Lab PC”, attempt 1 of 20`), when it succeeds (`Reconnected to “Lab PC”`), and when a session ends or fails to start, with the status screen's title, such as `Connection Timed Out`. Later attempts update only the desktop's value and the overlay text, so VoiceOver does not speak every attempt.
- The credentials sheet uses `credentialsUsername`, `credentialsPassword`, `credentialsDomain`, `credentialsRemember`, `credentialsCancel`, and `credentialsConnect`. The server's challenge decides the fields. A password-only challenge, such as classic VNC, shows no username. The domain appears only for RDP. After the server rejects the account, Reconnect shows the sheet again with the rejected values instead of resending them. The permission banner uses `shortcutPermissionNotNow` and `shortcutPermissionOpenSettings`. The screenshot note is `captureConfirmation`.

### Toolbar

The Home button is `home` and the + button is `newConnection`. Both are `NSButton` views with the toolbar bezel, because an image toolbar item has no public way to set an identifier; they look the same as bordered image items. ## Session capture

`SessionViewController.capture: SessionCapture` owns capture for one tab. `SessionCapture` is a main-actor observable object in RemoraCore. It takes constructor-injected `CaptureMedia` and `CaptureDestination` adapters. `AppleCaptureMedia` contains ImageIO, AVFoundation, Core Image, and VideoToolbox calls. `ScreenshotDestination` contains macOS location and filename policy. The app UI is described under "Capture UI" below.

The UI entry points on `SessionViewController` are:

```swift
let capture: SessionCapture
func takeScreenshot(copyToClipboard: Bool = false) async throws -> URL?
func startRecording() throws
@discardableResult
func stopRecording() async -> Result<URL, CaptureFailure>?
```

`takeScreenshot(copyToClipboard: false)` saves a PNG and returns its URL. Passing true puts the same PNG representation on `NSPasteboard.general` and returns nil. The clipboard operation lives in the AppKit controller. The portable capture object also exposes `screenshotPNG() async throws -> Data` and `saveScreenshot(connectionName:) async throws -> URL`.

Observe these properties on `capture`:

```swift
public private(set) var recordingState: RecordingState
public private(set) var lastSavedURL: URL?
public private(set) var recordingURL: URL?

public enum RecordingState: Sendable, Equatable {
    case idle
    case recording(startedAt: TimeInterval)
    case finishing
    case failed(CaptureFailure)
    public func elapsed(at uptime: TimeInterval = ProcessInfo.processInfo.systemUptime) -> TimeInterval?
}
```

The start time uses monotonic uptime, not a calendar date. The UI can use a timeline to show elapsed seconds without asking the encoder for updates. `lastSavedURL` changes only after a successful save or movie finalization. `recordingURL` identifies the reserved output while recording or finishing. Stop returns nil if no recording needs finishing. Concurrent stop callers await the same task. Starting before the first frame throws `CaptureFailure.noFrame`. Starting during recording or finishing throws `.busy`. Other failures use `.image(String)`, `.recording(String)`, `.file(String)`, or `.timedOut`, with localized descriptions. An encoder failure changes state to failed after the same stop path cleans up. Failure observation uses AVAssetWriter status observation and a bounded async stream, with no idle polling timer.

`MetalDesktop` owns the renderer's existing three staging slots, exact damage union, private BGRA texture, and serial command queue. `FrameRenderer` owns presentation and its display pipeline, and implements `FrameSink` directly. There is no capture fan-out and no separate CPU framebuffer. The ordinary session path still copies only dirty rectangles into the original staging slots. Capture adds a nil observer and one arrival timestamp to that state. With recording off, the only ingest-path difference is the nil check inside the existing lock. There is no capture copy, allocation, clock read, dispatch, timer, readback, or additional lock on the RDP thread. The previous dirty-rectangle mapping into a second app-specific array is also removed.

Screenshots use a one-time readback of that native-resolution texture. This is smaller than a new protocol framebuffer operation: the renderer already owns the complete desktop and the ordering needed to read it, so there is no new FreeRDP command, worker lock, callback lifetime, or VNC-specific implementation. `SessionCapture.screenshotPNG()` runs readback and ImageIO encoding off the main actor. Readback flushes any pending dirty uploads before copying the whole texture into a temporary shared Metal buffer. It waits for that command outside the ingest lock, then copies into the owned `CaptureFrame` used by ImageIO. Both temporary pixel buffers disappear after the operation. No new remote frame, display link, drawable, visible tab, or Screen Recording permission is needed. The image contains no Mac toolbar, window decorations, overlays, or local cursor.

The UI entry points, recording states, elapsed-time API, and saved URLs above are unchanged. The internal adapter interface changed: `CaptureFrameSink`, `SessionCapture.frames`, and the `frames:` initializer parameter were removed. `SessionCapture.setSource(_:)` attaches a `CaptureSource` when a renderer is created and detaches it when the session ends. `CaptureSource` exposes `size`, `snapshot()`, and `addFrameObserver(_:)` / `removeFrameObserver(_:)`. `CaptureMedia.movie(at:source:)` replaces `movie(at:initialFrame:)`. `CaptureMovie.submit(arrival:)` replaces `submit(_ frame:)`. The Apple movie adapter consumes `MetalDesktop`; VNC can use the same renderer without any capture changes. Old session callbacks have their own old renderer, so they cannot update a replacement session's source.

A recording begins with the current complete desktop. It uses AVAssetWriter, a video-only QuickTime movie, and HEVC. The top-level `AVVideoEncoderSpecificationKey` sets `kVTVideoEncoderSpecification_RequireHardwareAcceleratedVideoEncoder` to true. Hardware unavailability fails instead of falling back to software. The bit rate is four bits per desktop pixel per second, bounded to 2 to 40 Mbps. That gives about 8.3 Mbps at 1920 by 1080 and 33.2 Mbps at 3840 by 2160, retaining screen detail without allocating a high-motion camera bit rate to an idle desktop. Keyframes are at most two seconds apart. Frame reordering is disabled to reduce encoder buffering. Output color metadata is Rec. 709.

The movie adapter gets BGRA IOSurface-backed, Metal-compatible buffers exclusively from the adaptor's pool. A six-buffer allocation threshold bounds pool growth. While recording, a lightweight observer announces frame arrival after the renderer's original dirty copy. The one-element mailbox holds only the latest arrival time, not pixels. The recording worker flushes accumulated dirty uploads to the existing desktop texture, then GPU-copies that texture directly into a pool buffer. The RDP thread performs no extra recording pixel copy and never waits for an encoder operation. Matching dimensions with no visible overlay use a Metal blit. With overlays or a size change, Core Image composites the small overlay images over the texture and aspect-fits the result over opaque black within the initial recording dimensions. `SessionOverlayDrawing.agentCursor(_:)` rasterizes the halo, lift, and transformed glyph into one small Core Graphics sprite in desktop pixels. The compositor applies `CIGaussianBlur` only when that sprite has a positive blur radius during the first 0.3 seconds of appear. Human cursor images and rings retain the existing sprite path. The screen renderer reads the shared cursor pose into Core Animation layers in `AgentPointerView`. For the key press pill it draws the glass chrome from `KeyPressPill`, and the recorder blurs only the capsule's region of the frame under it. The drawing cache retains the current chrome image, glyph path, and human ring, with no desktop-sized CPU overlay allocation. A same-format texture view forces alpha to one for Core Image sampling, because the protocol's alpha byte is undefined. The writer and track dimensions remain fixed. Core Image's intermediate cache is disabled.

Presentation, screenshots, and recording reserve command queue order under the renderer's existing lock with `enqueue()`. Encoding the rest of a command, compiling Core Image kernels, waiting for GPU completion, allocating encoder buffers, and appending to AVAssetWriter all happen outside that lock. Every enqueued command is committed even if its consumer throws. Each taken staging slot is returned exactly once by command completion, or by dropping a still-pending upload. There is no second capture semaphore. Core Video texture wrappers stay alive until their GPU copy completes, and ARC owns the pool buffers and framework objects.

The arrival clock is process uptime, read only while the recording observer is installed. Presentation timestamps use the later of the copied texture arrival and the overlay update, relative to recording start, with the first sample at zero and a minimum interval of 1/60 second. The worker coalesces faster arrivals to the latest timestamp. When the input is not ready or the pool reaches its threshold, it retains that single pending timestamp and retries after 1/60 second. Retries stop when there is no pending change. Pointer movement and settings changes wake the same mailbox as desktop frames. `SessionOverlayState` also emits updates at 60 Hz while a human click ring, key pill, or unsettled cursor is alive, including travel, press, appear, hide, and sway. It wakes the thinking window even if no screen observer exists. Its timer stops after the last animation and thinking window expire. A static desktop without an active overlay animation submits no periodic frames. The recorder advances its pacing clock from the preceding deadline, rather than adding a full frame interval after GPU work. Finalization retains the last immutable pool buffer and appends it once at the stop timestamp, then ends the writer session at that same timestamp. This extends the encoded media through the final idle interval, including a recording with only one source frame. Ending the session alone extends AVFoundation's edit-list timing but can leave the actual media shorter, which other players report as truncated. Stop time is captured once on entry to movie finalization using the same uptime origin as frame timestamps. Stop, close, disconnect, and quit use that path, and a failed final append uses the ordinary typed failure and cleanup path.


The cursor snapshot contract is shared by the screen and recorder. `snapshot(at:)` advances the value model under the overlay lock using absolute monotonic uptime. A display link supplies `CADisplayLink.timestamp`; a recorder supplies its frame arrival timestamp. Both share the `ProcessInfo.systemUptime` / `CACurrentMediaTime()` time base. Older reads cannot rewind the model. Integration uses a fixed 1/480-second grid, with at most two seconds of catch-up before jumping to the current target. `arrivalDelay` steps a copy on that grid. The lock's observers only enqueue work and must never reenter the state synchronously.

`Snapshot.agentCursor` is an optional `AgentCursorFrame`. Its `pose` contains `center`, `hotspot`, `haloCenter`, and `blurRadius` in desktop pixels, with y growing downward; `rotation` is clockwise radians; `scaleAcross`, `scaleAlong`, `opacity`, and `haloScale` are dimensionless. `fill` is an unpremultiplied sRGB `CGColor`. `unit` is desktop pixels per spec point, from the shared `sessionOverlayUnit(scale:desktopHeight:) = max(scale, desktopHeight / 1080)` rule also used by `KeyPressPill`. Travel runs in desktop pixels divided by this unit. `isSettled` lets the screen stop its display link after the springs settle. The overlay observer wakes it for later changes and for the thinking window.

On screen one spec point is one view point. Map `pose.hotspot` into the desktop's view rectangle, then place the glyph at `tip_view + (pose.center - pose.hotspot) / unit` and the halo at `tip_view + (pose.haloCenter - pose.hotspot) / unit`. Apply the dimensionless rotation and shape scales to a one-point glyph, use `blurRadius / unit`, and scale the 36-point halo by `haloScale`. Clip to the desktop rectangle. Recordings use the desktop-pixel fields directly and scale glyph, stroke, and halo by `unit`.

`AgentPointerView` draws the screen cursor in a private `AgentCursorView` above the key press capsule. The view's frame is the drawn desktop rectangle, and its layer clips to it. A container layer carries opacity and holds the fog `CAGradientLayer`, the white lift `CAGradientLayer`, and a `CAShapeLayer` glyph built from `CursorGlyph.path()` with the `CursorStyle` outline. Each frame sets positions, transforms, fill, and the glyph's `CIGaussianBlur` inside a `CATransaction` with actions disabled. The blur filter is removed once the radius reaches zero. Every layer's `contentsScale` follows the window's backing scale. The cursor draws only while `showAgentPointer` is on and the pose opacity is positive.

The view's `CADisplayLink` runs in the common run loop modes and renders `snapshot(at: link.timestamp)`. It stops when the frame is settled, when the tab's desktop leaves the window, and when the window is occluded or minimized. The overlay observer, the window's occlusion and miniaturize notifications, and a return to the window start it again. The view only reads the model; `applyControl()` alone sets the cursor's visibility.

The incremental idle capture storage is the optional observer and arrival metadata, plus the session's source reference. There is no desktop-sized capture allocation. Recording adds the bounded encoder pool, texture cache, and one pending timestamp. At equal dimensions without visible overlays it adds one full GPU texture-to-pool blit per encoded frame, at most 60 per second, with no full CPU copy or Core Image pass. Visible overlays use a GPU Core Image pass; raster drawing touches only the small artwork images. At 3024 by 1964 each blit transfers 23,756,544 bytes, about 1.43 GB/s of GPU copy traffic at the cap. The renderer's normal dirty uploads remain shared with display. A Debug benchmark on this development Mac recorded a static 3840 by 2160 desktop with moving agent input, rings, and changing text at a steady 60 fps. Frame preparation through GPU completion measured 4.74 ms median and 5.64 ms p95 with overlays, versus 0.94 ms median and 1.60 ms p95 for the blit path. The first overlay frame took 25.34 ms while Core Image initialized. The glass key press rendition blurs only the capsule's region. In back-to-back runs of the same benchmark with the pill visible, it measured 6.0 to 7.3 ms median and up to 10.6 ms p95, against 5.8 to 6.2 ms median for the earlier opaque pill drawn without a blur. These measurements exclude the asynchronous hardware encoder and do not establish performance on other Macs.

Recording forces `SessionDisplay` updates on, including hidden tabs, minimized windows, and occluded windows. Stop removes that override and applies the current visibility and CLI frame demand. Automatic RDP reconnect keeps the capture object, movie, timeline, and update override. Frames resume in the same movie after reconnect, with any new desktop size fitted into the original video size. Terminal disconnect finishes the movie. A later manual connection attempt attaches a new renderer with no old desktop texture.

Stop, explicit disconnect, terminal session end, and controller teardown remove the renderer's recording observer before finishing the movie. Tab close and quit use the same controller disconnect path. `SessionTabs` retains captures from closed tabs until they finish, so quitting also waits for movies whose tabs have already disappeared. `AppDelegate.applicationShouldTerminate(_:)` disconnects sessions, returns `.terminateLater`, waits for all captures, and calls `reply(toApplicationShouldTerminate:)`. A pending frame has five seconds to drain. Movie finalization has an eight-second cancellation deadline. The app has a ten-second overall deadline and logs any unfinished destination and partial-file location before replying. Force Quit, process crashes, and power loss cannot run this teardown.

`ScreenshotDestination` reads `com.apple.screencapture` `location`, expands a tilde, and otherwise uses `~/Desktop`. An explicitly configured location that cannot be written produces a typed error rather than silently saving somewhere else. Names use local time, for example `Remora - Office - 2026-10-18 at 03.40.12.png` or `.mov`. Unsafe filename characters are replaced with hyphens. An exclusive file creation reserves the name; collisions add ` (2)`, ` (3)`, and so on. Movie encoding uses a unique hidden `.Remora-<UUID>.partial.mov` in that folder while the destination stays reserved. Successful finish atomically replaces that empty reservation. Failed writes delete the reservation and partial movie. A cleanup error reports the remaining path.

### Capture UI

The Session menu has Take Screenshot (Ctrl-Option-Cmd-S), Copy Screenshot (Ctrl-Option-Cmd-Shift-S), and Start Recording (Ctrl-Option-Cmd-R). The screenshot items are enabled only on a connected session tab. Menu validation retitles the recording item from the shown tab's `capture.recordingState`: Start Recording on a connected tab, Stop Recording while recording, and a disabled Finishing Recording... while the movie finalizes. Copy Screenshot is a visible item rather than an Option alternate, because an alternate of a four-modifier shortcut shows only while all four keys are held, and HIG asks not to hide a primary action behind an alternate. The three shortcuts are in `SystemShortcutCapture.staysLocal`, so they work while the desktop has the keyboard. The shown tab's actions menu has the same three items. Each names its tab through `representedObject`, and the actions and validation use that tab's session.

Each tab that records shows a red `record.circle` symbol in place of the status dot, to the left of its title, including hidden tabs. Recording needs a connected session, so the green dot it replaces carries no information. `SessionTabView` reads `tabs.session(for: id)?.capture` in its body, so SwiftUI observation updates it directly. The symbol differs from the status dot in shape and color: the dot is a solid 7-point circle in green, orange, or gray. Like Safari's audio button in a tab, clicking the symbol stops that tab's recording. While the movie finalizes, the symbol is dimmed and disabled. Its tooltip gives the elapsed time, computed from `RecordingState.elapsed(at:)` when the body evaluates; hovering the symbol reevaluates it, so there is no timer or redraw loop. Accessibility adds "recording" or "finishing recording" to the tab's value and a Stop Recording action. The toolbar has no recording control: the tab strip already covers every tab, and a toolbar item would show only the shown tab.

A saved or copied screenshot shows "Screenshot Saved" or "Screenshot Copied" in a small glass capsule at the bottom of the desktop for 1.5 seconds, then fades out. It ignores the pointer and is not part of any capture, because captures read the renderer texture. It plays the system Screen Capture sound unless the user turned off user interface sound effects (`com.apple.sound.uiaudio.enabled`), and posts an accessibility announcement. No notification permission is needed.

A start or screenshot failure shows a "Capture Failed" warning sheet with the failure's localized description. Every stop path ends in `onRecordingActivityChange(false)`, which awaits the shared stop result once, so user stop, encoder failure, and disconnect report a failure exactly once. When cleanup cannot remove a reserved or partial file, the core's description names its path, so the sheet shows it. A failure on a hidden tab marks it with the orange dot and shows when the tab shows. It waits in its own slot, so it never replaces a pending credentials or certificate request; AppKit shows the second sheet after the first ends.

When any tab records or finishes a recording, the quit alert adds "Recordings in progress are saved." Quit shows no capture UI and is bounded by the ten-second finalization deadline above.

## VNC backend

`VNCSession(configuration:frameSink:inputFeedback:)` implements `RemoteSession` and the core `AgentInputSession` contract. `Connection.Kind.vnc` defaults to 5900; RDP retains 3389 and its existing JSON representation. A protocol change replaces the old default port while preserving an explicitly supplied or custom port. Older binaries do not understand VNC records and may quarantine the entire connection file as invalid. Keep a connection-file backup before downgrading.

One worker owns LibVNCClient, all protocol writes, decoding, framebuffer storage, and held input. A mutex protects admission, cancellation, pending commands, and the socket handle. DNS uses the cancellable `DNSServiceGetAddrInfo` descriptor with a five-second limit. Nonblocking TCP connect has a ten-second total limit. A twenty-second initialization watchdog also covers TLS and authentication; an outstanding user challenge suspends it. Disconnect shuts down the published socket and signals the DNS/connect wake descriptor. It resolves a pending challenge and pending agent receipts before the terminal event stream finishes. LibVNCClient has a ten-second incomplete-read timeout. Explicit disconnect interrupts incomplete reads immediately. No detached DNS worker survives cancellation.

The native client negotiates Tight, ZRLE, Hextile, CopyRect, or Raw through LibVNCClient. Borrowed BGRA frames use the existing `FrameSink`, Metal desktop, screenshots, and movie capture. Damage pointers remain valid only within the synchronous callback. Frame allocation is limited to 256 MiB. The server owns geometry. ExtendedDesktopSize enables client resize only for a successful single-screen layout. A successful ExtendedDesktopSize acknowledgment emits a geometry event even when no new framebuffer allocation is needed. The requested flag comes from the wire origin. Standard status 4 means the request was forwarded for asynchronous application. It preserves resizing support and does not change framebuffer geometry. A later origin-0 success supplies the actual dimensions with `requested: false`; the CLI waits for those actual dimensions. An administrative resize prohibition (origin 1, status 1) disables resizing for the remainder of that connection. Later layout notifications still update actual geometry but cannot override the prohibition. A waiting CLI resize returns `unsupported` when VNC resize support is withdrawn. Reconnecting starts a new capability negotiation. Other request errors can recover after a valid layout advertisement. Multi-screen layouts remain server-owned. Fixed saved dimensions cannot force a VNC server to resize. Hidden views may continue receiving frames because this backend does not implement display-update suppression; resuming requests a full redraw.

Security negotiation reads the entire server offer before selecting. VeNCrypt wins over classic methods regardless of server order. Only X509None, X509VNC, and X509Plain subtypes are allowed, with TLS 1.2 or newer. A failed secure handshake never retries a weaker method. Anonymous TLS, plaintext VeNCrypt Plain, SASL, UltraVNC MSLogon, and RSA-AES are unsupported. If VeNCrypt is absent, an unfamiliar advertised security type prevents fallback to classic methods. Servers offering only classic VNC, None, or Apple ARD can connect, but their desktop transport is unencrypted. Classic VNC authentication uses at most the first eight password bytes by protocol design. ARD encrypts authentication, not subsequent desktop traffic. No operating-system profiles alter negotiation.

Certificate TLS verifies chain and DNS/IP identity against `/etc/ssl/cert.pem`. A user can explicitly trust a leaf SHA-256 fingerprint after a validation failure. Once a pin exists, it is checked even if a replacement certificate has a valid CA chain. A changed leaf requires a new decision. Chain failures always identify the leaf rather than an intermediate. Fingerprints are stored per normalized host and port in `~/Library/Application Support/Remora/VNC/certificates`; `certificateStoreURL` supplies a separate directory for isolated verification. A trusted tunnel endpoint uses its configured host as the certificate identity. Trusting a mismatch is an explicit fingerprint decision, never a disabled verification setting. The committed upstream patch also serializes OpenSSL initialization, waits for new socket bytes while exact reads are incomplete, and reports parsed authentication failures and resize status to the adapter.

Credential prompts identify `.password` for classic VNC and `.usernamePassword` for Plain/ARD. VNC has no domain. A rejected password ends the attempt with `authenticationFailed`; the user can reconnect with new credentials. Cancellation is distinct from certificate rejection, DNS failure, refusal, and timeout. VNC has no automatic reconnect in this version.

Human and agent keys and buttons have separate owners. Releasing one source preserves the other's held state. An admitted agent request has at most one pending send; acknowledgment means protocol submission. Cancellation discards its queued input. `finish()` sends source-specific releases outside task cancellation and closes the transport if the release cannot finish within two seconds. Standard keysyms work without an extension; negotiated QEMU extended key events preserve physical positions. Human character keysyms retain the original down symbol for release. The public-domain libxkbcommon table preserves legacy Unicode keysyms, including EuroSign. Command maps to Super, Option to Alt, and Control to Control. Wheel fractions accumulate per source; wheel pulses preserve held buttons. Horizontal scrolling is supported; back/forward buttons are unavailable. RFB has no portable lock-state synchronization, so focus synchronization does not guess remote lock state.

Extended Clipboard transfers UTF-8 text when advertised. Otherwise text uses lossless ISO-8859-1. Text outside that fallback alphabet reports `.failed` rather than replacing characters. Text is bounded to one MiB. Incoming text is decoded according to its negotiated encoding. Clipboard availability and revision events use the existing `RemoteClipboard` model.

Live verification used Debian 13.7, labwc 0.20.2, and wayvnc 0.10.2 on a Raspberry Pi Compute Module 4 through an isolated loopback SSH tunnel. The tested security mode was VeNCrypt X509Plain (262), TLS 1.3, with a self-signed certificate containing localhost and 127.0.0.1 SANs. Native tests covered trust acceptance/rejection/persistence, changed-pin detection with a seeded prior pin, wrong credentials, prompt cancellation, immediate disconnect, real framebuffer delivery, Metal PNG capture, German Unicode text including Euro, agent Shift surviving human release, pointer press/release, both wheel axes, bidirectional UTF-8 clipboard, cursor shape/hotspot, server/client resize, hidden-view resume, and a finalized HEVC movie decoded back into changing frames. The seeded-pin test did not rotate the remote certificate. Other security modes remain implementation support, without live interoperability claims. Loopback regression tests interrupt an incomplete greeting and an incomplete raw rectangle and verify that terminal cleanup wakes an admitted agent send.
